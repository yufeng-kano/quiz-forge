# 清單頁一律當工作區，不要短表漂在空白裡

文件庫截圖暴露的問題（浮動圓角卡片、表格縮成一條、底下整片白、長標題橫向捲）不是只有 `/documents`。本決策把同一條版面規則套到其他「一張表就是整頁」的畫面，並點名不套用的頁。

## 決策

### W1. 單一 DataTable 主體頁 = 工作區

下列頁在頁首以下吃滿剩餘視窗高度；表格列再少，表面也拉到底，空白留在表內。

- `/jobs` 任務中心
- `/conversations` 選題助手歷史

篩選列（任務的狀態／種類）貼在表格上方，與表同一塊工作面，不是另掛一張 `.card`。不要為了「看起來有區塊」再包一層圓角邊框。

標題欄吃剩餘寬度、單行 ellipsis。不得再給標題儲存格設死 `max-width`（選題助手歷史目前的 `36rem` 與文件庫的 `34rem` 是同一類錯誤）。

列上的單一動作（歷史頁的「刪除」）可留文字鈕；若欄寬不夠就進 overflow 選單，與文件庫同一套元件。

### W2. 文件詳情的頁面大綱不是卡片

`/documents/:id` 左側頁面導覽與文件庫資料夾欄同一語彙：滿高側欄、中間一條分割線、無外框圓角底。內容區（頁面 Markdown、分段）仍可依段成塊，那是閱讀面不是清單工作區。

### W3. 不套用本決策的頁

這些頁的主體不是「一張表填滿視窗」，維持現況，不為了整齊硬改成工作區。

- `/` 總覽：數字卡 + 近期任務是 dashboard，卡片網格是對的。
- `/questions`、`/review`：題目本來就是一張一張卡片，篩選列當 toolbar 即可，不把題庫改成滿高表格。
- `/generate`：表單 + 本 session 任務列，是出題工作台，不是檔案庫。
- `/exports`：選題、表單、進行中任務、歷史疊在同一頁；歷史表不要為了吃滿高度去排擠表單。
- `/usage`：四張合計卡 + 兩張對照表。兩表並排可以，但不必為了吃滿高度重排整頁。
- `/conversations/:id`：對話頁已經是訊息區可捲、輸入框釘底，不在本決策範圍。

### W4. 實作順序

先落地 `docs/decisions/2026-08-17-documents-workspace-layout.md`（文件庫 + DataTable 撐滿模式 + overflow 選單）。本決策的 `/jobs`、`/conversations`、文件詳情大綱接同一套，不另做第三種表格高度。

## 理由

- 一看就不專業的共同原因是「內容高度 = 列數」，列少時整頁塌成上緣一條卡片。檔案庫／任務表／歷史表在正規軟體裡都是「框先在，列填進去」。
- 出題、審題、匯出、總覽不是檔案庫，硬套滿版表格會犧牲它們本來該有的表單或卡片結構。

## 影響

- `docs/frontend.md` 的工作區規則從「目前是文件庫」擴大到任務中心與選題助手歷史。
- `DataTable` 撐滿高度模式會被這三頁共用。
- 功能不變：篩選、排序、輪詢、刪除對話、開啟對話。
