# 文件庫改為滿版工作區

使用者判定 `/documents` 文件庫「難看」、不像正規軟體。當下畫面是標題列＋獨立 tab 列＋左側資料夾卡片＋右側短表，表格下方整片空白，長標題把列撐出橫向捲軸。本決策重畫文件頁版面。

## 決策

### L1. 文件頁是單一工作區，不再用兩個 tab 當主結構

- `/documents` 永遠是文件庫：左側資料夾欄＋右側表格，兩者一起吃滿頁首以下的剩餘視窗高度。
- 「上傳檔案／網址匯入」改由頁首主按鈕打開 Modal，不再是與文件庫並列的第二個 tab。
- 解析進度看表格列本身（既有 `DocumentStatusCell` 輪詢）。進行中或失敗的份數可用表格上方一行摘要提示，不另做整塊卡片清單。
- `?tab=upload` 仍可用：進入頁面時打開上傳 Modal；關掉後用 `replace` 拿掉該 query，`/documents` 與 `/documents?tab=library` 不得變成兩種看起來不同的網址。
- 上傳或匯入成功後留在文件庫，toast 回饋，新列出現在表裡。

### L2. 資料夾欄是側欄，不是卡片

- 無外框、無獨立圓角底。與表格共用一條垂直分割線即可。
- 欄本身拉滿工作區高度；清單超過時只捲這一欄。
- 「新增」用欄頭圖示，不在欄尾放教學句。拖放提示不得常駐佔高；只在尚無任何自建資料夾時，空狀態寫一句怎麼開始。
- 拖放到資料夾仍可移動文件；列選單「移至資料夾」仍必須保留（拖曳不能是唯一做法）。

### L3. 表格吃滿右欄

- 即使只有一列，表格表面仍拉到工作區底，不縮成一小塊再在底下留白。
- `table-layout: fixed`。標題欄吃剩餘寬度，單行 ellipsis，完整標題與來源網址放 `title`。拿掉標題儲存格自己設死的最大寬度。
- 來源／狀態／頁數／時間欄固定窄寬、不換行。狀態維持純文字加語意色，不是膠囊。
- 列動作收到 overflow 選單（開啟、改名、移至、刪除、必要時重試），列上只留一個觸發鈕，避免四個文字鈕把列撐出橫向捲軸。
- 搜尋列貼在表格上方，與表是同一塊工作面，不是另掛一顆小輸入框。

### L4. 設計系統只為這次需要補兩樣

- `DataTable` 增加由父層撐滿高度的模式（文件庫使用）。其他頁維持現有「內容多才長高、超出再內部捲」的預設，不得被這次改壞。
- 新增共用的 overflow 選單元件給列動作用。選單是浮層，可用既有 `--shadow-md`；頁面上的資料夾欄與表格本身不加陰影。

## 理由

- 檔案庫類軟體（Finder、雲端硬碟）的辨識特徵是「側欄＋滿版清單填滿視窗」，不是一疊圓角卡片漂在空白裡。
- 解析中的文件本來就在庫裡，第二個 tab 只是把同一列再畫一次，卻多了一層 chrome 與一大段空白。
- 橫向捲軸來自標題欄沒有真正把剩餘寬度吃完，加上列上堆了多個文字動作。

## 影響

- `docs/frontend.md` 文件區從「兩 tab」改為「滿版文件庫＋上傳 Modal」。
- `AppTabs` 目前只給文件頁用；文件頁不再用它。元件可留在設計系統，不強制刪。
- `DocumentActiveList` 不再掛在文件頁。進行中摘要若要做，另寫一行，不重用那張卡片清單。
- 功能不變：資料夾 CRUD、拖放移動、改名、刪除、單份重試、上傳／網址匯入、client-side 標題搜尋與排序。
