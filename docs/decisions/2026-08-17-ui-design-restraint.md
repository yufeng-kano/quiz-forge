# UI 設計節制原則（去裝飾、去廢字）

## 背景

前面幾份決策（頁首精簡、狀態去 tag、清單工作區、題庫去套疊卡片）都是同一個方向的個別修正：畫面被卡片、膠囊、灰色小字與說明句撐開，資訊密度反而變低。這份把方向寫成全站通則，之後所有頁面一體適用，不再一頁一頁補決策。

原則：每一條邊框、底色、陰影、圓角、膠囊與**每一個字**都必須承載資訊。說不出它告訴讀者什麼，就不該存在。畫面要讀起來像「一整塊有分區的工作面」，不是「一盤磁磚」。

## 決策

### D16 卡片不是版面骨架，禁止卡中卡

- 版面結構一律靠 grid/flex、間距、分割線與標題階層做出來，不靠一疊圓角白框。
- 卡片只有兩個正當用途：框住一個有界捲動區，或框住一組真正獨立的資料集。最多一層，不得嵌套。
- 覺得需要卡中卡時，是外層容器選錯了：要嘛內層才是卡片、要嘛兩層都不該是卡片。

### D17 pill／badge／chip 只留封閉集合的短詞

- 只有「封閉集合、單行放得下」的值可以做成 pill：狀態詞、題型、計數。
- 開放內容（標題、分類名、使用者輸入、任何可能變長的字串）一律用純文字加語意色。pill 不能折行，在有界欄位裡會被自己的邊框從字中間切斷。
- 不得為了「看起來有設計」把值包成 pill。狀態呈現延續 `2026-08-17-compact-headers-and-job-errors.md`：純文字＋語意色。
- 例外仍是控制項：已選文件／分類的可移除 chips 是操作元件，不是狀態裝飾。

### D18 有慣用 icon 就不要放字

- refresh、copy、close、add、edit、search、expand 這類使用者不用 hover 就認得的動作，一律 icon-only，文字進 `aria-label` 與 tooltip（文案仍走 locale 檔，不硬編碼）。
- 只有兩種情況留文字：沒有公認 glyph，或這個動作罕見且後果重（誤點會掉資料，例如刪除、丟棄整批）。

### D19 不重述外框已經說過的事

- 側邊欄已標記目前所在頁時，頁面不需要再用標題重複那個詞，更不需要一句解釋這頁是幹什麼的。
- 頁內同理：內容自明的區塊不需要標題，欄位上方已有 label 就不需要下方再補註解。使用者剛剛點過的上下文不是資訊。
- 唯一例外是無障礙名稱：`aria-label`／視覺隱藏文字要保留。

### D20 不寫沒人要的輔助文字，尤其不用灰色小字

- 每個標題下不配副標、每個欄位不配提示、每個控制項不配說明。label 加資料通常就是完整設計。
- 文案要靠「告訴使用者畫面上還沒說的事」換到位置，否則刪掉。
- 灰色 11px 小字是最便宜的裝飾、最貴的閱讀成本。重要就給可讀的字級與字重；不重要就刪。不准用「縮小＋轉灰」當折衷。

### D21 邏輯獨立的區域各自捲動

- 每個獨立區域自己界定高度、自己擁有捲軸。兩個區塊共用一條捲軸，代表版面根本沒分區，使用者得捲過一份資料才碰得到另一份。
- 延續 `2026-08-17-bank-on-questions-page.md` D13（題庫左右欄分開捲）與 `2026-08-17-list-pages-workspace.md`（清單工作區吃滿剩餘高度），擴大為全站通則。

### D22 先用最樸素的手段做出區別

weight 與顏色優先於 chip，分割線優先於面板，間距優先於邊框。能用更輕的手段表達的區別，就不要升級成框。

## 理由

- 這是單人自用的工作系統，使用者每天看同幾個畫面；裝飾與說明句第一次看是「友善」，第十次看就是每次都要跳過的噪音。
- 卡片疊卡片會產生兩層內距與兩層邊框，實際可讀寬度被吃掉，長標題與表格更容易被截斷。
- pill 在 `table-layout: fixed` 的窄欄裡是明確的視覺瑕疵（邊框切過文字），已在題庫與文件頁出現過。
- 專案已有的頁首精簡、去 tag、去套疊卡片決策都指向同一件事，寫成通則可以省掉之後每頁再吵一次。

## 影響

- `docs/frontend.md` 新增「設計節制原則」節，作為前端實作與檢視的合規基準。
- 全站九個功能頁與 `src/components/` 需依此檢視：卡片層數、pill 用法、icon-only 動作、多餘標題與說明句、灰色小字、捲動區切分。
- 既有決策不被推翻，只是被擴大成通則；衝突時以本決策為準。
