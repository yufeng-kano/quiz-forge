# 題庫工作區加分割線與左右出血

使用者在題庫頁標出兩處：選取列（已選取／前往匯出／清除選取）與題目清單之間要一條分割線；右側選題助手要「一體性的感覺，不要感覺是插入的」。右欄目前縮在 `.page` 的 gutter 內，與全寬的頁首底線對不齊，垂直分割線比頁首窄一截，看起來像後貼上去的一塊。

## 決策

### B1. 題庫 toolbar 底下加分割線

- `.bank__toolbar`（檢視 tab、篩選、選取列、未向量化提示、錯誤訊息所在的那塊）加 `border-bottom`，與文件庫搜尋列的語彙相同（L7：控制列與清單同一塊，一條線收尾）。
- 線吃滿左欄整寬，不是縮在內容 padding 裡面。

### B2. 題庫工作區左右出血，與頁首底線同寬

- `.bank` 用與 `PageHeader`、文件庫 `.workspace` 相同的水平負 margin（`calc(-1 * var(--content-padding-x))`），左右貼齊 `.app-main`。
- 選題助手與主區之間的垂直分割線因此與頁首底線同寬、上下齊整，兩欄是同一塊工作區而不是插入的側欄。
- 左欄各 band（toolbar、清單、分頁）自己補回水平 padding，字不貼邊；toolbar 的分割線仍吃滿欄寬。
- 右欄（選題助手）內部既有 padding 維持，只因為出血而貼到頁面右緣，不得再加一層外框 padding。
- 窄幅（單欄堆疊）時出血維持，分割線照舊轉成橫向。

## 理由

- 文件庫已經證明「出血＋欄內自帶 padding」是這套系統的一體感語彙（L7／L8）；題庫右欄是同一類分欄工作區，用同一語彙才有全站一致性。
- L8 寫「任務中心、題庫不要順手出血」，那是防止未經要求亂改；本決策是使用者明確要求題庫右欄一體化，只推翻 L8 對題庫的那一句，對任務中心維持。

## 影響

- `docs/frontend.md` 題庫頁與視覺風格補兩句：toolbar 分割線、工作區出血。
- 實作：`QuestionBankView.vue` 的 `.bank` 出血、`.bank__toolbar` 加 `border-bottom`、左欄各 band 補水平 padding。
