# 選題助手改為獨立歷史頁與對話頁

日期：2026-08-17

## 背景

`docs/decisions/2026-08-17-bank-agent-semantic-selection.md` 的 D7 把選題助手做成題庫頁（`/questions`）右側可收合面板。實作後同一畫面同時放：

- 題庫篩選、分頁、勾選列、補向量提示
- 對話切換與刪除
- 訊息、提案卡片、「查詢過程」、輸入框

結果是題庫瀏覽與對話互相搶空間，窄視窗還要靠浮動按鈕進出。使用者明確要求：不要把功能全擠在同一頁；第一頁只留新增與歷史清單，點進去才是簡潔的對話頁。

D1–D6（題目向量、語意搜尋、有界迴圈、只提案不改選取、對話持久化）不在這次範圍，行為不變。

## 決策

### D8 選題助手脫離題庫頁，改為獨立路由

- `/conversations`：歷史列表。`PageHeader` 右側只有「新增」圖示按鈕；內容只有對話歷史清單，沒有訊息、沒有輸入框、沒有題庫篩選。
- `/conversations/:id`：單一對話。只有該則對話的訊息、回合進度與輸入框；沒有對話下拉、沒有歷史清單、沒有題庫篩選列。
- 側邊欄新增「選題助手」，放在「題庫」與「匯出」之間。`/conversations/:id` 沒有獨立 nav 項，高亮同一項（比照 `/documents/:id`）。
- 題庫頁還原單欄。語意搜尋（`similar_to`）與未向量化提示仍留在題庫，那是瀏覽題庫的工具，不是對話的一部分。

理由：歷史與對話是兩種工作，不該跟題庫勾選共用一塊面板。獨立路由才能各自保持簡潔，並讓網址對到一則對話。

### D9 歷史頁與對話頁職責分開

- 新增：`POST /api/v1/conversations` 建立空對話後立刻進入 `/conversations/:id`，標題仍等第一則使用者訊息由後端截斷寫入。
- 進入既有對話：點歷史列。刪除可在歷史列動作或對話頁 header，都走既有 `DELETE` 與 ConfirmDialog。
- 對話頁不提供「切到另一則對話」的控制項；要換對話就回到歷史頁。
- 「套用到篩選」仍寫入題庫頁的篩選 store，並導向 `/questions`，因為套用後要看的是題庫清單，不是對話。
- 回合 job 仍由對話頁用既有 `useJobPolling` 訂閱。離開對話再回來，靠 store 裡記得的 `pendingTurn.jobId` 重訂閱；重整頁面則下次載入對話時直接讀已寫入的訊息。不在 App 層常駐輪詢。

理由：第一頁只回答「要開哪一則」，第二頁只回答「這一則說了什麼」。輪詢綁在對話頁，避免為了收一則回覆又把助手掛回題庫。

## 被推翻的決策

- **D7 右側欄可收合，不動既有版面結構**：作廢。題庫不再掛選題助手面板，也不再持久化收合狀態。

## 代價與風險

- 側邊欄從 8 項變 9 項；窄幅仍是 icon-only，可接受。
- 從對話套用篩選會離開對話頁，回來要再點一次歷史。這是換頁的代價，換來兩頁各自乾淨。
- 既有對話資料與 API 不改；這次只動前端資訊架構。
